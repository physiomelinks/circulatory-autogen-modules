1. Rule text for modules/README.md "Placement and naming"

  1. Name by mechanism. A module type is named after the mechanism it models (Ca_handling, membrane_potential, ion_concentrations, neurotransmitter_release, i_Na, ...), never after the cell, compartment, system or author it was built for. Type names never carry surnames or years.
  2. Placement. A type sits in the most general category where its mechanism is meaningful: Ca handling exists in every cell, so cell/Ca_handling; ion channels, pumps and exchangers are cell/ion_channels/<channel>.
  3. Nesting. Nest a type only when it is an anatomical part of its parent: cell/neuron/{soma,axon,varicosity}, heart/{chamber,valve,cardiac_clock}. Parts are supermodules whose versions are cell or organ types (soma/sympathetic). No directory name appears twice in the tree, and no two sibling categories or types mean the same thing (one heart/, no cardiac/).
  4. Version or instance: compare the equations.
    • Different maths is a version, named <system>_<compartment>_<Source><Year>_vXX (Ca_handling/versions/SN_soma_Argus2026_v01), or <system>_<Source><Year>_vXX without a compartment (membrane_potential/versions/cardiomyocyte_Paci2013_v01), or <Source><Year>_vXX where the system adds nothing (ion channels: i_Na/versions/Tao2011_v01). Source is the first author's surname in ASCII CamelCase (HernandezCruz1997); the owner's unpublished or modified models use ArgusUNPUBLISHED; an SI-unit duplicate adds _SI; a superseded formulation ends _OLD.
    • Same maths with different parameter values is an instance of the existing version (versions/<v>/instances/<instance>).
    • Vessel-network modules keep their port prefix first (vp_wCont_ASD), because libcuflynx reads a module subtype's first two letters as its inlet/outlet port kinds (see "Boundary-condition prefix" for the exact rule and for non-vessel modules).
  5. One mechanism across cell types. Modules of the same mechanism built for different cells or compartments join one type as versions or instances (rule 4). Versions of one type expose compatible ports where the mechanism allows; where they cannot (e.g. a bond-graph pump beside current-law pumps), the type's report says which ports differ.
  6. required_citations. Every version's modules_config.json entry has "required_citations": [bib keys]: the papers whose model the version's equations come from (not the per-parameter value sources, which stay in the CSV data_reference). Each key is in the version's references.bib and follows <surname><year><first significant title word>, all lowercase (belluzzi1986quantitative). A supermodule lists its own and its report and exports add its submodules'.

Superseded: the "most specific place covering its uses" rule, the SN_ part names, and the 2026-10-02 rename table where it conflicts (the SN parts were to become soma_…/varicosity_… types with version Argus2026_v01; they now join mechanism types as SN_soma_/SN_varicosity_Argus2026_v01; lung_bg_Argus_Chase → lung/ArgusChase_v01 becomes lung_mechanics/ventilated_ArgusUNPUBLISHED_v01; Gee 2023 versions become ArgusUNPUBLISHED instead of Gee2023_v01; Ca_dynamics, Na_dynamics, electric_potentials become Ca_handling, ion_concentrations, reversal_potentials). Kept from it: surname-free control types, Ursino1998 joining efferent_resistance_effector, GeeArgus2026_v01, _2 → _SI, _OLD → version.

Computed check of every post-rename version name (non-vessel types only; a name is at risk when it does not start with nn and its first two letters end in p or v): none at risk.
What this means.
  • Every connection (CVSCellMLGenerator __check_input_output_modules, called for each module pair): if neither side starts with nn, the first two letters are read as port kinds: a module whose BC_type[:2] ends in v must feed one starting with p, one ending in p must feed one starting with v, otherwise generation stops (exit()). So a version named lv_…, rv_…, Up… or Sp… breaks its connections; SN_, cardiomyocyte, Argus, Paci, Tao, HernandezCruz, Ursino, GeeArgus, ventilated pass silently. This is why the heart_effector versions keep nn_.
  • Min_junction / Nout_junction / MinNout_junction (CVSCellMLGenerator): every neighbour whose BC_type[:2] is not nn is treated as a vessel joined at the junction ("otherwise K_tube modules or other non-vessel modules will also be included"). A non-vessel module named e.g. ArgusUNPUBLISHED_v01, SN_soma_…, cardiomyocyte_…, lv_… wired to such a junction would be taken for a vessel. The schema note "exempts names starting nn" is therefore the whole rule: anything else counts.
  • Terminal inputs: a vessel with a terminal among its inputs and BC_type.startswith('v') gets a venous connection. Only vessels have terminal inputs.
  • 1D coupling (ModelParsers, CVSCppGenerator): inlet BCs next to a 1D vessel must start nn; heart vessel types are read by BC_type[1].
  • Supermodules are expanded before any of this (utilities/supermodules.py), so soma/sympathetic, heart/Argus2026_v01 etc. are never read.

Cell modules: never wired to junctions, terminals or 1D vessels, so the proposed SN_…, cardiomyocyte_…, ArgusUNPUBLISHED_v01 cell versions are safe (as the existing Argus2026_v01 ion channels already are). Control, organ, respiratory and coupling modules can sit next to junctions: today only nn-prefixed ones do (below), so nothing breaks now, but a renamed control version wired to a Min/Nout junction later would.

(B) Without the fix, non-cell, non-vessel versions keep nn_ first: nn_ArgusUNPUBLISHED_v01, nn_lv_ArgusUNPUBLISHED_v01, nn_Ursino1998_v01, nn_GeeArgus2026_v01, nn_ventilated_ArgusUNPUBLISHED_v01 (the existing nn_SI, nn_lv style).
